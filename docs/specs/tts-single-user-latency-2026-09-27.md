## Work plan
1. Inventory source, relevant tests, deployment records and existing experiment evidence. Record baseline revision, runtimes and tests. Establish whether target-representative isolated CPU execution is actually available.
2. Trace complete user-visible flow: assistant events -> preparation -> first-fragment speculation -> cache -> foreground playback -> subsequent fragments -> stop/restart.
3. Scheduling: verify manual-start/continuation priority, pending background suppression, running background behavior, multiple tabs/leases, lease expiry, bounded queues, fairness and stale session replacement. Reproduce failures with deterministic tests before fixes.
4. Deduplication/cache: verify text/config/revision identity, first-fragment consistency between speculation and playback, concurrent foreground/background joining, revision invalidation, cache budgets/TTL and failures. Avoid caching incompatible output or repeated work.
5. Cancellation/errors: verify stop, expired clients, late results, backend-unknown outcomes, retries, task cleanup, failed candidates and no unbounded retry loops.
6. Segmentation/early start: verify first and follow-up chunk boundaries, punctuation/Markdown/normalization contracts, stable assistant-final trigger. Evaluate earlier stable-sentence speculation only if event semantics and byte-identical prefix matching are proven; do not speculate on mutable tokens or increase background load blindly.
7. Implement minimal confirmed fixes in cohesive batches. Add regression tests for each. Keep established API and model-quality contracts.
8. Logic acceptance scenarios: idle prefetch hit; click during matching prefetch; click during unrelated prefetch; foreground start during metadata/preparation; multiple finished chats; stop/restart; expired tab; network timeout; changed model/lexicon revision; cache eviction; long text and technical Markdown. Confirm no duplicated synthesis, runaway background loop or stale playback.
9. CPU optimization gate: only after logic checks, use existing benchmark/profiler tools and representative target. Fixed parts: preprocessing, synthesis/vocoder, audio assembly. At most 10 total candidate experiments for this run, with 3 consecutive non-KEEP stopping a part; within four-hour total budget. One attributable change per experiment, quality gate, warmup, balanced paired measurements and holdout confirmation. Skip unsupported parts explicitly; no unmeasured speed claims.
10. Profile first. Prefer removing redundant computation/copies and reusing data over SIMD/assembly. SIMD only for a measured owned hotspot and with portable fallback/equivalence tests. Never modify upstream ORT kernels speculatively.
11. Final acceptance: focused plus full applicable JS/Rust tests, security review for changed boundary/cancellation/network behavior, self-review with independent-review availability honestly noted, README for changed public behavior, task-only commits and concise results/handoff.
