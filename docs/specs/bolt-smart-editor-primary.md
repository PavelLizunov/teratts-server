## Architecture and boundaries

Verdict: Extend — existing dependency-free Bonsai HTTP transport/gateway seam plus pinned llama.cpp b11459 and the proven Bolt profile. No package installation, alternative engine or model download. Prior four native cases are contextual evidence only and are consumed; new production-profile cases must be distinct.

- New explicit `BOLT_NORMALIZER_CONFIG` takes priority over FrogNano/Bonsai without falling through when invalid. Gateway invocation remains smart-only and one-call/no-retry. Keep legacy headers and expose actual model/revision.
- New pinned Bolt client reuses the bounded transport, fixed dictation system prompt and lexical invariants. It must consume the validated model answer rather than silently reconstruct R76 local cleanup. Preserve protected quote/code/technical/literal spans exactly, including repeated occurrences and malformed-quote abstention. Unsupported substantive deletions must fail closed. A finite source-span deletion policy may admit supported additional profanity/emotional-only spans, but may not generically bless deleted clauses just because they lack a number/negation. Preserve all other source characters except local separator/capitalization changes at cuts. No R77 local-cleanup-after-ignoring-answer behavior.
- New serial stdlib Mac service, authenticated Tailnet endpoint (new port 8094), launches the exact trial llama-server on a private loopback ephemeral port per request, shared vision.lock, verifies full model hash at service startup before becoming ready, pins its stable file identity and rejects any subsequent stat drift before each inference; validates runtime manifest hashes per request; same embedded template and reasoning-off settings. Health/models do not load weights. Stop/reap task-owned process before successful response and release lock only after cleanup. No permanent resident Bolt weights, no second model fallback.
- Use model repo/revision/hash and runtime identity from the retained isolated assessment. Production model ID is the official repo; the internal alias is only a native identity. Maximum 6000 chars, 3072 prompt tokens including BOS, 512 output tokens, 4096 context, greedy seed42, f16/f16 KV, mmap/lazy PLE, no warmup/cache/speculation. Outer transport max20s; native operation budget18s including cleanup. Resource gates: admission proxy6.5GiB, sampled reserve2GiB and swap growth0.25GiB. These are sampled controls, not instant peak guarantees.
- Preserve token secrecy and content-free logs. Reuse existing authorization/token retrieval, but never copy credential values to Git or reports. Reject redirects, malformed/duplicate JSON/framing, unsupported profiles, non-EOS/truncated/reasoning output or effective-template drift.
