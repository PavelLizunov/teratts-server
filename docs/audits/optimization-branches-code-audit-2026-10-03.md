## Главные находки, в порядке действий

### 1. Средняя серьёзность: предупреждение безопасности rustls

В [Cargo.lock:1436–1437](<../../Cargo.lock#L1436-L1437>) закреплена версия 0.23.43, совпадающая с [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285.html). RustSec указывает исправление **0.23.45 и выше**, CVSS 5.3. Проблема — принятие TLS 1.3 сообщений на неправильном уровне шифрования; это **не доказательство перехвата или подмены аутентифицированного handshake**.

Reqwest использует rustls, HTTPS нужен загрузчику моделей. Локальный HTTP primary и входящий Axum HTTP — не этот TLS-путь; внешний Tailscale HTTPS обслуживается отдельно. Версию библиотек реально запущенного бинарника в этой задаче не проверяли, поэтому активную эксплуатацию или экспозицию не утверждаем.

**Действие:** отдельная небольшая задача на transitive lock-update rustls, проверку diff, сборку/тесты на разрешённом worker и HTTPS-путь загрузчика. Не требуется ради этого автоматически переходить на reqwest 0.13.

Проверка OSV охватила все **246 registry-пакетов** lock-файла. Второе уведомление — [paste не поддерживается](https://rustsec.org/advisories/RUSTSEC-2024-0436.html); это информационный риск сопровождения через tokenizers, не подтверждённая уязвимость. [Данные проверки](<optimization-20261002/registry-security.json>).

### 2. Средняя: ревизия кэша не описывает реально использованный словарь и backend

- Health читает последнюю загруженную ревизию словаря, но изменение файла само не вызывает refresh. Если повторный текст берётся из кэша, запрос до сервера не доходит и словарь может долго оставаться невидимым для кэша. Обещание «TTL 30 секунд» касается health-запроса, не обнаружения правок словаря.
- `/tts` захватывает ревизию до выполнения refresh словаря; первый ответ после изменения может быть помечен старой ревизией.
- Gateway отдаёт звук primary с собственной ревизией и не переносит идентичность реально использованного primary. Обновление primary при неизменном gateway не обеспечивает правильную инвалидизацию.

Источники: [server:304–311](<../../src/server.rs#L304-L311>), [server:570–580](<../../src/server.rs#L570-L580>), [server:929–955](<../../src/server.rs#L929-L955>), [remote_primary:145–191](<../../src/remote_primary.rs#L145-L191>), [Host:369–406](<../../dsh-plugin/lib/index.js#L369-L406>). Host-половина воспроизведена изолированно; Rust-половина подтверждена исходным порядком операций, **не новым Rust integration-run**.

**Действие:** привязать ревизию к точному эффективному snapshot и backend, обеспечить безопасную публикацию reload/инвалидизации. Не делать файловый I/O синхронно в async health. Добавить тесты cached-repeat после правки словаря, primary-update, fallback и смены настроек во время запроса.

### 3. Средняя: длинные языковые теги ломаются в CLI

[CLI:309–320](<../../src/main.rs#L309-L320>) сначала режет сырой текст по предложениям, потом нормализует отдельные части. Корректный `<en>…</en>` длиннее лимита упаковки может превратиться в части с незакрытым открывающим и отдельным закрывающим тегом. HTTP использует другой, языково-осведомлённый путь; на него этот дефект не распространяется.

[Диагностический пример](<optimization-20261002/source-path-results.json>) воспроизводит исходную логику без моделей. **Действие:** preprocess один раз, затем языково-осведомлённый chunking; добавить CLI-тесты длинных RU/EN span и ручного ударения.

### 4. Средняя: автоматический rollback может выбрать не прежнюю активную версию

[rollback:16–20](<../../deploy/linux/rollback.sh#L16-L20>) выбирает каталог с самым новым временем изменения, исключая текущий. Установленная, но никогда не активированная новая версия выигрывает у прежней рабочей. Точный selection pipeline воспроизведён на временных синтетических каталогах; сервисы не запускались.

**Действие:** пока указывать SHA явно. В отдельной задаче хранить идентичность последней успешной активации и проверять откат к ней.

### 5. Низкая: небольшой лишний запрос и две ошибки вспомогательных контрактов

- [Host:318–344](<../../dsh-plugin/lib/index.js#L318-L344>): первое prepare-сохранение получает ключ старой ревизии; второй одинаковый запрос повторяет подготовку. Режим prepare включается отдельно. Изолированный реальный Cordis-сервис подтверждает два вызова, затем hit.
- [speech-text:138–146](<../../dsh-plugin/lib/speech-text.js#L138-L146>): secondChars не валидируется как first/next. Публичные настройки используют корректные default; риск ограничен нестандартным вызовом helper.
- В экспериментальной ветке [review UI:4](https://github.com/PavelLizunov/teratts-server/blob/be99bc74a13637b15cffbfb4ccc929b587cd71a7/tools/vocabulary-bank/review-ui/app.js#L4) приоритет операторов направляет `/github` и `/linux` на вкладку blind. VM-проверка подтверждает.

**Действие:** точечные исправления с regression-тестами, без перестройки системы.

[Подробный пакет находок и отклонённых подозрений](<optimization-20261002/pinned-branch-findings.md>). Ошибочные первоначальные предположения о пропавших модулях словаря и необёрнутом RPC исключены после проверки.

## Все ветки: что переносить

- `fix/server-markdown-default`, `fix/tts-dsh-020-compatibility`, `perf/phase2-cpu-tuning`, `agent/speech-latency-gpu`, обе локальная/удалённая phase3 и локальная speech-front-remediation: изменения уже в main. Локальный main отстаёт на 10 коммитов, но отдельной потерянной разработки там нет.
- `agent/speech-front-integration`: один «уникальный» коммит истории уже попал в main через squash `31581d9`. **Stable patch-id совпадает**, затем main получил дополнительные исправления. Не сливать старую ветку повторно.
- `perf-autoresearch/teratts-opt`: 8 коммитов вне main. Buffer-reuse затем отменён; browser cleanup уже заменён более новой main-реализацией; перенос именованного lowercase не меняет число преобразований. Main уже выполняет настоящий inference warmup при `TERATTS_WARMUP=1` и создаёт normalizer при startup; эти идеи не являются отсутствующими исправлениями. Дополнительный eager preload всех стилей можно обсуждать отдельно после измерения cold/warm/RSS. Изменения CPU/memory лимитов — изменение ресурсов, не доказательство эффективности. **Не делать wholesale merge.**
- `task/private-voice-deep-hooks`: 21 коммит вне main, 73 изменённых файла. Это новая телеметрия и source-only резервные копии внешних STT/Model Forge инструментов, не только оптимизация. Main ушёл вперёд на четыре собственных коммита. **Разделить runtime telemetry и внешние tooling/backups**; сохранить latest main fixes, определить приватность/capability gating и выполнить отдельную runtime/browser проверку перед активацией.
- `task/optimization-branches-code-audit-20261002`: только отчёт и доказательства; автоматическое слияние не входит в задачу.

Ветки не удалялись. Исторические коммиты имеют GitHub-копии; отдельная чистка веток — необязательная будущая операция.

## Оптимизации: что доказано

**Оставить в main:** graph options/mimalloc, opt-in engine pool, bounded speculation/foreground leases, согласование фрагментов, ограничение отмены/повторной отправки и нынешнее исправление malformed-Markdown. Эти механизмы имеют source/regression-проверки, но это не новое измерение скорости рабочей системы.

**Надёжный узкий результат:** старые paired данные очистки Markdown пересчитаны; search median **169,379 → 0,624 мс**, confirmation **321,267 → 1,026 мс**, по 6 пар, артефакты quality совпадают по SHA. Frozen full-v1 quality-check сейчас прошёл с negative controls. Это снижение стоимости специально повреждённого текста, **не ускорение нейросинтеза**. [Пересчёт](<optimization-20261002/historical-paired-analysis.json>).

**Исторические ориентиры:** CPU 3,65→2,3–2,5 с и GPU сравнения записаны в прежних документах; без текущего hardware/config/runtime снимка они не описывают сегодняшнюю задержку. Числа в раннем research-плане «до X раз» — гипотезы, а не acceptance.

**Не подтверждать как выигрыш:** legacy autoresearch 3,24→2,98 с. Нет достаточного paired/memory/perceptual-пакета для final combination; ресурсные лимиты менялись. Quality helper проверяет WAV/размер, не произношение/ударения и не полноценную perceptual parity. Захват stderr в PIPE без drain создаёт риск зависания расширенных прогонов. Эти скрипты следует исправить до нового использования.

**INT8:** выключен по умолчанию; случайные calibration float inputs, включая mask, не репрезентативны. Пока не повышать в production. Полный WAV/RTF — не TTFA; инструментам нужен явный status/header validation и разделение метрик.

## Актуальные технологии и обновления

[Подробный обзор с первичными источниками и ограничениями](<optimization-20261002/technology-review.md>).

- **ONNX Runtime 1.30.0** доступен, deploy pin — 1.27/API27. Возможные CPU kernel/thread improvements требуют одинаковых ресурсов, ABI/glibc проверки и quality gate. Первый кандидат после исправлений корректности; [релиз](https://github.com/microsoft/onnxruntime/releases/tag/v1.30.0).
- **ort rc13** уже актуален по найденному upstream; модель TeraTTSv2 имеет ту же опубликованную ревизию. Нет доказанного нового model-release для замены.
- **17 прямых зависимостей** проверены: flate2 и tokenizers имеют patch-update; reqwest/sha2/toml — новые несовместимые линии. Не обновлять всё ради номера версии. Rust 1.99 доступен, найденная локальная toolchain — 1.98.
- **Sampler4, streaming и GPU I/O Binding** — реальные технические варианты, но нуждаются в отдельной короткой проверке качества/TTFA/копирований. KV-cache GenAI-подсказки не относятся напрямую к diffusion TTS.
- **Piper 1.8** — CPU/RU fallback-кандидат с проверкой лицензии конкретного голоса; **Qwen3-TTS** — RU/GPU quality/streaming-кандидат, не drop-in; **Kokoro** не имеет установленной официальной RU-поддержки и не предлагается как русская замена.
- **DSH:** реальный установленный protocol/Client Gateway тестируется успешно. Публичные latest endpoints не установили более новую совместимую версию; старый npm latest tag — не повод для downgrade.

## Поддерживаемость, размер и документация

- Большие Rust-файлы содержат встроенные тесты; lexicon — данные. Не декомпозировать по числу строк. При будущей работе извлекать только реальные доменные границы: request admission, preparation/revision и inference orchestration.
- В private-ветке две идентичные копии gateway и две копии corpus-модуля. Это source backups внешней системы; дать им владельца/единый источник, а не развивать параллельно как Tera runtime.
- sample_latent и synthesize_preprocessed повторяют оркестрацию графов. Возможен небольшой shared helper при реальной дальнейшей поддержке; не нужен большой tensor framework.
- Малый словарь не требует speculative trie. Host/browser helper parity тестируется; устранение необходимой shipping duplication требует настоящего общего build-источника, не третьей ручной копии.
- README актуально описывает Markdown/prepare, ресурсные и retry ограничения. Ранние specs/checklists/топологии сохраняются как история; не использовать их как активную конфигурацию. License gate весов Tera остаётся: отсутствие явного upstream разрешения на распространение подтверждённым обновлением не снято.

## Выполненная проверка и пределы

- Main Node: **126 passed**, private Node с profile peers: **135 passed**.
- Private Python: **88 passed** (48 vocabulary, 14 dictionary, 7 full corpus, 3 pilot, 14 teacher, 2 mocked Ultra). Все 47 branch Python файлов прошли AST; JS и shell syntax — успешны.
- Диагностические Node-проверки — успешны; source-derived CLI и временный rollback-selection — успешны; frozen evaluator quality/manifest и legacy manifest SHA — успешны.
- Rust тесты **не запускались**: обнаруженный Cargo guard запретил компиляцию на control-plane. Не обходили его. Исторические 146 passed/4 ignored относятся к совпадающему исходному main, а не новой проверке этой задачи.
- Не проверены active remote binaries/config, настоящее качество звучания/TTFA, перцептивное сравнение альтернатив и exhaustive interleavings. Ни одного Critical/High дефекта не подтверждено; это не security certificate.
